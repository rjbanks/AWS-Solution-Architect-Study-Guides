Exam traps

Alias does not directly target arbitrary EC2 hostnames. CNAME cannot be used at the zone apex. A private zone that matches but lacks a record does not simply fall back to public DNS.
DNS failover is not instantaneous. Route 53 does not proxy requests. Traditional public health checkers cannot reach private IPs; alarm-based checks are the classic exam solution. Newer private endpoint health checks use a VPC health check source.
Newer AZ-affinity routing prefers the query's AZ with broader location fallback; lower priority for classic SAA preparation. Do not confuse latency with geography.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

DNS choices

Use Alias A/AAAA for supported AWS targets (including zone apex); use CNAME for arbitrary hostname at a subdomain; use A for a fixed IPv4 address. Alias to an AWS resource follows changing target addresses; TTL is inherited from target, not separately set.

Routing priorities

Choose latency for expected network speed; geolocation for user location and localization; geoproximity for geographic bias; weighted for proportional DNS answers; failover for active/passive. Multivalue returns up to eight healthy answers but does not balance individual requests.

Health and failover

With ELB Alias records enable Evaluate Target Health where supported. Standard public checks probe HTTP/HTTPS/TCP periodically; use 30s or 10s intervals and a configurable failure threshold. With all records unhealthy, some policies can still return unhealthy answers; DNS is not a hard traffic block.

Hybrid DNS

Inbound resolver endpoints accept forwarded queries from corporate DNS; outbound endpoints forward selected domain suffixes to on-prem DNS using rules. Configure private connectivity, security groups and IP addresses across AZs; enable both VPC DNS attributes for private zones.

Migration sequence

Lower old record TTL ahead of change, wait out previous TTL, change target, validate, and restore normal TTL. Registering a domain and creating a hosted zone are separate; delegate using the zone's authoritative NS records.

Exam traps

Public subnet alone does not give an instance internet access. NAT gateway is not a firewall, and an IGW handles public IPv4 translation for an instance with a public IPv4 address.
Deploy a NAT gateway per AZ and route locally for resilient public NAT egress. A gateway endpoint is not PrivateLink and is not a general internet route.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Trace the route first

For IPv4 public EC2: public IP + subnet default route to IGW + permitted traffic. The IGW performs one-to-one public/private IPv4 translation. For private EC2: default route to public NAT gateway in a public subnet, NAT EIP, NAT subnet default route to IGW. No inbound connections initiated through NAT.

Endpoint selection

S3/DynamoDB gateway endpoints use route tables and endpoint policies, no hourly endpoint fee. Interface endpoints use private ENIs, security groups, endpoint policies where supported and private DNS. Prefer these over NAT for private API calls; consider data processing and hourly charges.

Resilient subnet design

Use at least two AZs with public ALB subnets, private application subnets and isolated database subnets. For classic zonal public NAT gateways, route each private subnet to a NAT in its own AZ to avoid a shared failure dependency and cross-AZ charges.

IPv6 paths

IPv6 addresses are globally routable; an egress-only IGW permits outbound-initiated IPv6 traffic without unsolicited inbound. NAT64 with DNS64 can help IPv6-only workloads reach IPv4 destinations; ordinary IPv4 NAT is not the IPv6 answer.

Route troubleshooting

Longest prefix match wins. Route tables select next hop; SGs and NACLs decide allowed traffic. A missing route cannot be fixed with a security group. VPC CIDRs must not overlap for peering; reserve address space for growth.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Security groups vs NACL

SG rules are additive allow rules at ENI level; stateful replies do not need separate rules. NACL rules are ordered, first match, allow or deny, stateless at subnet boundary. NACLs need both request and response paths.

Three-tier policy

ALB SG allows 443 from intended clients; app SG allows application port from ALB SG; DB SG allows engine port from app SG. Prefer SG references instead of wide CIDRs. Private database does not need public IP or internet route.

Ephemeral port logic

Client connects from a temporary source port to server port 443. For stateless NACLs, server subnet ingress allows 443 and egress allows client ephemeral destination ports; client subnet egress allows 443 and ingress allows ephemeral return ports. Use the actual OS/client range.

Diagnose access

Reachability Analyzer evaluates network configuration; Flow Logs show accepted/rejected traffic metadata; neither is packet payload capture. Use CloudWatch for application metrics/logs and Traffic Mirroring when packet inspection is required and supported.

Explicit deny vs filtering

Use a numbered NACL deny for an unwanted IP at a subnet boundary, WAF for HTTP attack patterns and Network Firewall for managed VPC network inspection. Do not attempt to add a deny rule to an SG.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Topology choice

Peering connects two VPCs privately and is non-transitive; TGW centralizes transitive routing among many VPCs and hybrid networks; PrivateLink exposes a specific service without full network routing and supports overlapping address spaces.

VPN vs DX

Site-to-Site VPN is encrypted IPsec and quick to provision. Direct Connect is a dedicated connection with consistent network performance, but not encrypted by default. Use VPN over DX or eligible MACsec when encryption is required. Plan redundant connections for HA.

Bandwidth and ECMP

Classic Site-to-Site VPN tunnels can support up to 1.25 Gbps per tunnel under suitable conditions. TGW ECMP with equal-cost dynamic BGP paths can distribute flows across eligible tunnels; not a way to exceed physical circuit capacity or guarantee one flow is faster. VGW does not provide VPN ECMP.

Transit routing

Attachments associate with a TGW route table and may propagate routes. Segment environments with multiple TGW tables; explicitly configure VPC subnet routes to TGW. Inter-Region TGW peering requires static routes for the remote prefixes.

Service sharing

Typical PrivateLink provider publishes an endpoint service behind an NLB; consumer creates interface endpoint ENIs. No public IP required. Choose Client VPN for individual remote users, not Site-to-Site VPN.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Purchasing decisions

On-Demand for short or uncertain workloads; Spot for interruptible stateless/batch jobs; Savings Plans or RIs for predictable use; On-Demand Capacity Reservations for AZ-specific capacity assurance. A regional RI discount does not reserve capacity.

Placement groups

Cluster packs instances close for high throughput/low latency (typically one AZ); spread separates hardware for a small number of critical instances; partition divides instances into isolated hardware partitions for distributed systems.

Storage and lifecycle

EBS-backed instance stop/start retains attached EBS and may change public IPv4; instance store data is lost on stop/termination. Reboot normally preserves instance store. Use EIP or load balancer for a stable endpoint; verify delete-on-termination settings.

Deploy and administer

AMI is image; launch template captures instance configuration such as AMI, instance type, SG, IAM instance profile and storage. User data typically runs at first boot. Use Systems Manager Session Manager instead of opening SSH when prerequisites are met.

Tenancy and licensing

Default tenancy is shared hardware; Dedicated Instances use dedicated hardware without host-level placement visibility; Dedicated Hosts provide host-level visibility and licensing control. Match VPC and launch tenancy; do not assume default template tenancy overrides dedicated VPC tenancy.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Layer and protocol

ALB is L7 HTTP/HTTPS, host/path routing, redirects and target groups; NLB is L4 TCP/UDP/TLS with static IP per AZ and high network performance; GWLB is for transparent virtual network appliances using GENEVE.

Target health

Configure health check path/port for meaningful readiness. ALB can fail open when all targets are unhealthy; health checks are not an authorization boundary. ASG can use ELB health checks in addition to EC2 status to replace failed instances.

Scaling policies

Target tracking maintains a metric target (e.g., average CPU or ALB requests per target); step scaling reacts to alarm breach magnitude; scheduled scaling handles known time patterns; predictive scaling forecasts recurring demand. Scale workers using SQS backlog per instance.

Capacity and sessions

Min = lower bound, desired = target, max = upper bound. Instance warmup prevents premature scaling decisions. Keep app state outside instances (ElastiCache, DynamoDB or database); sticky sessions can help legacy sessions but are not durable state.

AZ and deployment

Use ALB across at least two AZs and ASG in private subnets. NLB static IPs fit allowlisting; ALB has DNS endpoint, not fixed IP. Deregistration delay allows in-flight requests to drain. Use weighted target groups for HTTP-level canary routing.

Exam traps

S3 is not block storage. Storage classes have different minimum duration and retrieval charges. Cross-Region replication is asynchronous and not automatic for old objects.
S3 website endpoints do not support HTTPS directly; use CloudFront. Use REST origin + OAC for private buckets, not website endpoints. CORS is not authorization.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Storage class choice

Standard for frequent reads; Intelligent-Tiering for unknown/changing access; Standard-IA for infrequent multi-AZ reads; One Zone-IA for recreatable data; Glacier Instant Retrieval for rare millisecond reads; Flexible Retrieval / Deep Archive for restore-before-read archives.

Encryption and access

Default SSE-S3 encryption protects new uploads unless configured otherwise; SSE-KMS adds key policy, audit and key control; bucket keys can reduce KMS request costs. Block Public Access + private bucket + least-privilege policies. Presigned URLs grant time-limited access using signer's permissions.

Replication and recovery

CRR/SRR require versioning on source and destination, replication role and appropriate KMS permissions. New eligible objects replicate asynchronously; existing objects need Batch Replication. Versioning enables recovery from accidental overwrites/delete markers; Object Lock protects versions under retention/legal hold.

Website and delivery

S3 website endpoint serves static site HTTP only; for private HTTPS content use CloudFront with S3 REST origin and OAC. For large worldwide uploads choose S3 Transfer Acceleration when network path is bottleneck; multipart improves transfer parallelism and retry efficiency.

Consistency and events

S3 has strong read-after-write and list consistency for object operations. Notifications are at-least-once and can be out of order; design idempotent handlers. S3 direct event destinations include standard SQS/SNS and Lambda; use EventBridge for FIFO SQS routing.

Exam traps

EBS volumes are AZ-scoped. Multi-Attach has restricted volume and instance requirements and needs cluster-aware applications. EFS is not native SMB.

Final-week architecture decisions

Focus on the requirement, select the service, and remember the constraint that rules out the alternatives.

Select the protocol

EBS = block device for EC2 in same AZ; EFS = shared NFS file access for Linux; FSx Windows = SMB with AD; FSx Lustre = parallel file storage for HPC/ML with S3 integration. S3 = object API, not a mountable general-purpose block device.

EBS performance

gp3 lets IOPS and throughput be provisioned independently from size within limits; gp2 performance is tied to size with bursting for smaller volumes; io2 for demanding predictable IOPS; st1 for large sequential throughput and sc1 for colder sequential data. HDD volumes cannot be boot volumes.

EBS resilience

EBS snapshots are incremental and can restore volumes in another AZ in the Region or be copied across Regions. Snapshots are not synchronous replicas. EBS Multi-Attach is limited to supported Provisioned IOPS volumes/instances within one AZ; application coordinates writes.

EFS access patterns

Regional EFS stores data across AZs and can provide mount targets per AZ; One Zone trades resilience for price. Lifecycle policies move eligible files to lower-cost classes; performance/throughput modes are separate choices. Use security groups to permit NFS port 2049.

Hybrid storage

S3 File Gateway provides NFS/SMB backed by S3 with local cache; Volume Gateway supplies iSCSI block volumes with snapshots; Tape Gateway integrates existing backup applications with virtual tapes. DataSync transfers data rather than providing a persistent gateway interface.

Queue mechanics

SQS standard: at-least-once, best-effort order. FIFO: ordered within message group and send deduplication within five-minute window; consumers still need idempotency. Visibility timeout hides a received message; delete only after successful processing. DLQ isolates repeated failures using maxReceiveCount.

SNS fan-out

EventBridge vs MQ

Decoupling and resilience

Scale SQS workers by backlog per instance, not only CPU. Ensure visibility timeout exceeds processing time or extend it; handle duplicates; use long polling to reduce empty receives. SQS buffers demand; SNS is push delivery, not a general work queue.
